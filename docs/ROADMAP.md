## macOS 界面与交互设计

本阶段覆盖菜单栏、统计主窗口和从推荐进入改键的路径。已有原生控件、翻译和后端验收记录可继续使用。界面完成度单独评估。

| 顺序 | 交付 | 怎么验收 |
|---|---|---|
| 1. 统一语言和状态 | 梳理正常启动、启动失败、暂停、锁屏、解锁和语言切换时的菜单。统一状态、操作和窗口标题的语言来源；保留错误详情供排查。 | 分别使用中文和英文，切换后重开菜单、重启应用；检查所有用户可见状态和操作。隐私受阻时能看懂原因和可用动作。启动时读不到已保存的语言偏好，整份菜单使用同一种回退语言。 |
| 2. 设计菜单和主窗口 | 先做菜单、统计概览和快捷键详情的可点击原型。菜单呈现状态和当前可执行的操作；概览回答本周期常用哪些快捷键、是否有值得查看的建议；详情承载左右键位依据、应用分布和排序说明。 | 用同一组样例对照旧版与原型。首次打开的用户能看懂采集状态、找到常用快捷键，并从一个条目进入详情。空数据、暂停和受阻各有可理解的呈现。 |
| 3. 设计改键与设置 | 让一个推荐能顺着选择后端、预览改动、应用或导出、验证及恢复走完。按使用目的组织常规设置、隐私、备份和高级操作。 | 用 Karabiner 和 VIA 各走一条流程，核对预览、恢复入口和删除前复核。受阻时界面说明当前能做什么。 |
| 4. 原生实现与走查 | 将原型落实到 AppKit 菜单和 SwiftUI 窗口，统一字号层级、留白、分组、按钮和状态样式。 | 检查冷启动、语言切换、窗口缩放、深浅色、键盘焦点和 VoiceOver。涉及统计的页面同时检查锁屏后隐私内容及时隐藏。 |

[界面设计任务](DESIGN.md)记录了当前菜单和统计页的具体问题。首版菜单与统计主流程已经评审通过并接入原生界面。后续设计聚焦改键与设置，并在安装版上走查 VoiceOver 和完整操作流程。

## 下一阶段的顺序

1. **优先开展 macOS 界面与交互设计。** 接续已实现的菜单和统计主流程，设计改键与设置。
2. **并行补目标平台的来源证据。** macOS 14+ / Intel 是完整 v1 目标，但当前可靠锁屏读取只启用 arm64 macOS 27+。应在目标平台确认来源后定向接入，不能直接删除已有平台限制。
3. **执行受控后端与恢复验证。** Karabiner 本机重载、行为、清理和停用延迟已有记录。VIA 已完成一把键盘在 Mac 模式下的文件往返。接下来检查 Vial 只读 HID 和断连、密码恢复与卸载。每轮明确版本、隔离资料库/配置、恢复副本和动作范围。
4. **完成平台体验与资源测量。** 验证真实辅助功能权限、键盘/VoiceOver、双语界面、更新查询及规定时长性能；离线 AX 与构建不能替代。
5. **最后执行发布链。** 使用已实现的发布工具完成实际 Developer ID 签名、公证、staple、Gatekeeper、下载安装和首次启动，取得证据后更新支持目录。尚未公开发布。

已完成的离线工程批次见 v1 开发计划，后续优先级见上表；上面的来源与隐私决定边界继续有效。正式产品名已确定为 KeyRecord，项目自有代码许可为 Apache-2.0。

来源一致性、蓝牙命名空间、明确布局选项及旋转不再作为“未实现”重复排期。历史物理动作、活动层/时序和软件执行顺序仍缺足够来源；扩大采集范围需要单独决定，否则保持当前逻辑回退。

## 继续保留的边界

- VIA 使用用户主动导出最新配置 → 导入 KeyRecord → 手动导回 VIA 的文件流程；浏览器当前实例绑定、维护 VIA 分支/扩展均不是前提。
- 文件格式/键码的离线兼容不等于设备协议、已加载定义、在线导入器或真实键盘效果。保留结构、层入口、可达性、不透明内容及恢复检查。
- Karabiner 推荐保留组合与应用作用域；VIA/Vial 当前编辑器只接可表达的全局基础改键，不降级推荐原意。
- Vial 定义取自同次设备读取，不借用 VIA 几何。两次定义一致也不构成持续监听或全设备原子快照证明。
- 物理次数/跨度只在完整且可比较的证据链成立时独立展示，不改变逻辑排名；型号匹配、空属性或一次快照均不足以建立完整链。
- Karabiner 和 VIA 的单机结果见[当前状态](PROJECT_STATUS.md)。其他设备、真实 Keychain 恢复、完整卸载和发布验证仍待安排。删除前复核保留，脏主目录只读。
- 不默认新增 hash、冻结 contract、baseline 或 gate，不削弱已有安全措施，不恢复定时任务。

历史批次见 [ROADMAP_HISTORY](ROADMAP_HISTORY.md)，其中旧“下一步”不覆盖当前执行计划。完整目标见 [PRD](PRD.md)和[架构 §15](TECHNICAL_ARCHITECTURE.md#15-分阶段交付与发布门禁)。
