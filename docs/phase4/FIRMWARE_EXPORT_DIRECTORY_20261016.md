# 固件文件导出目录替换修复

> 历史记录说明（2026-10-20 核对）：本页保留所述日期/提交的实现、命令和验证范围，其中“当前”“待实现”“下一步”仅指当时。功能开发已暂停，最新状态见 [PROJECT_STATUS](../PROJECT_STATUS.md)，后续安排见 [ROADMAP](../ROADMAP.md)；本页不授权新实机、设备或删除操作。

基于 main `8923b107397e0135949e0c5366dfb4f33a5529e2`，延续用户主动导入／导出的 VIA 文件工作流。该文件目标实现也用于 Vial 文件和原始恢复副本导出。

## 具体失败场景

创建导出目标后，将选中的父目录移走，再在原路径创建同名目录。原实现按路径重新打开文件：新目录中无文件时会创建导出文件，存在相同内容时则覆盖它。内容检查无法区分两个不同目录；既有事务记录也不能限制操作系统实际写入的位置。

在真实临时目录中分别复现“目标不存在”和“目标已有相同内容”两种情况，修复前原生 Swift 包测试实际运行产生 6 个断言失败。日志为 `/private/tmp/keyrecord-firmware-directory-red.log`。

## 修复

导出目标现在持有选中目录的打开句柄，沿用 Phase 3 已实现的相对目录原子写入。读取、文件身份检查、临时文件创建、重命名、失败清理及目录同步均使用该句柄。读写前后核对原路径仍指向该目录；目录被替换或变成符号链接时拒绝操作。

最初通过符号链接选择的父目录会在选择时解析并绑定。之后修改该链接不会把已有目标重定向到另一目录。原目录内的普通文件原子替换仍可读取和覆盖，保存的目标引用也继续指向选中的实际目录。

复用已有文件句柄与原子写入实现，没有新增 hash、持久化 baseline、冻结 contract 或 gate。现有隐私权限、单链接／属主／普通文件检查、JSON 限制、加密原始副本和删除前复核均保留。不能据此声称排除了任意并发写入者在最后一次文件内容检查之后修改文件的所有竞态。

## 回归与自审

新增四项包测试覆盖目录替换、符号链接替换、已选链接重定向与合法文件原子编辑，以及导出事务记录保存后、实际写入前发生目录替换的恢复路径。最后一种情况必须保留两处文件及加密原始副本，不记录成功导出或用户导入。

相关固件事务、Karabiner 文件事务及共享持久化崩溃回归共 50 项通过，其中包含既有的最后检查后目录移动、重命名与临时文件清理测试。自审检查了句柄在初始化失败和析构时关闭、权限作用域释放、缺失目标文件分支、符号链接路径、正常文件替换和事务恢复。

本地全量 791 项包测试、96 项原生测试通过，Debug 测试构建和未签名 arm64／x86_64 Release 构建通过。日志位于 `/private/tmp/keyrecord-firmware-directory-package.log`、`/private/tmp/keyrecord-firmware-directory-native.log` 及同前缀构建日志；临时日志可能被清理，相关测试会在 CI 中持续执行。

所有操作使用临时目录、合成文件及测试密钥。真实设备 HID、真实 Keychain 恢复、真实卸载和发布验证继续后置，生产支持目录未放开。
