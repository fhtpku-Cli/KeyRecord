## 下一阶段的顺序

1. **先补目标平台的来源证据。** macOS 14+ / Intel 是完整 v1 目标，但当前可靠锁屏读取只启用 arm64 macOS 27+。应在目标平台确认来源后定向接入，不能直接删除已有平台限制。
2. **执行受控后端与恢复验证。** 依次检查 Karabiner 重载/行为/清理/停用延迟、VIA GUI 文件往返、Vial 只读 HID 和断连、密码恢复与卸载。每轮明确版本、隔离资料库/配置、恢复副本和动作范围。
3. **完成平台体验与资源测量。** 验证真实辅助功能权限、键盘/VoiceOver、双语界面、更新查询及规定时长性能；离线 AX 与构建不能替代。
4. **最后执行发布链。** 使用已实现的发布工具完成实际 Developer ID 签名、公证、staple、Gatekeeper、下载安装和首次启动，取得证据后更新支持目录。尚未公开发布。

当前执行批次以 v1 开发计划为准；上面的来源与隐私决定边界继续有效。正式产品名已确定为 KeyRecord，项目自有代码许可为 Apache-2.0。

来源一致性、蓝牙命名空间、明确布局选项及旋转不再作为“未实现”重复排期。历史物理动作、活动层/时序和软件执行顺序仍缺足够来源；扩大采集范围需要单独决定，否则保持当前逻辑回退。

## 继续保留的边界

- VIA 使用用户主动导出最新配置 → 导入 KeyRecord → 手动导回 VIA 的文件流程；浏览器当前实例绑定、维护 VIA 分支/扩展均不是前提。
- 文件格式/键码的离线兼容不等于设备协议、已加载定义、在线导入器或真实键盘效果。保留结构、层入口、可达性、不透明内容及恢复检查。
- Karabiner 推荐保留组合与应用作用域；VIA/Vial 当前编辑器只接可表达的全局基础改键，不降级推荐原意。
- Vial 定义取自同次设备读取，不借用 VIA 几何。两次定义一致也不构成持续监听或全设备原子快照证明。
- 物理次数/跨度只在完整且可比较的证据链成立时独立展示，不改变逻辑排名；型号匹配、空属性或一次快照均不足以建立完整链。
- 真实设备、Keychain 恢复、真实卸载和发布验证后置。删除前复核保留，脏主目录只读。
- 不默认新增 hash、冻结 contract、baseline 或 gate，不削弱已有安全措施，不恢复定时任务。

历史批次见 [ROADMAP_HISTORY](ROADMAP_HISTORY.md)，其中旧“下一步”不覆盖当前执行计划。完整目标见 [PRD](PRD.md)和[架构 §15](TECHNICAL_ARCHITECTURE.md#15-分阶段交付与发布门禁)。
