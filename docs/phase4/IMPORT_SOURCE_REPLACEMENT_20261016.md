# 导入文件被替换后的参考撤销

基于 main `0ab7dad45c85e5612d47cce202cc8051e147f63f`，继续 VIA 最新配置文件工作流。

## 复现

先导入合法配置和键盘定义，再移动它们的父目录，在原路径创建同名目录及文件。旧实现只依赖已打开文件的异步事件通知；替换父目录没有使子文件监听及时失效，配置字节、按键概况和几何参考仍然可取用。

实际原生测试分别使用内容不同和内容相同的替代文件，修复前产生 6 个断言失败。日志为 `/private/tmp/keyrecord-import-replacement-red.log`。这不是浏览器实时绑定问题，而是已经选择的本地文件路径发生了变化。

## 修复范围

共享文件监测器在读取状态时，补充核对该路径的普通文件类型、设备号／文件身份、大小以及修改和元数据变更时间。比较对象来自最初打开文件后的系统状态；不新增 hash、持久化 baseline、contract 或 gate。

一旦发现变化，立即返回失效并沿用现有通知路径撤销参考。即使随后把旧目录移回原位，也不会恢复已失效的选择，必须重新选择文件。异步文件事件继续保留，检查不依赖事件先到达；取消监测后也不能继续取用参考。

该读取器供 VIA 配置、VIA 定义、Vial 文件读取及 Karabiner 配置副本共用。仅定义文件失效时，配置字节和单文件概况仍可用，但矩阵／几何匹配结果撤销。重新选择合法定义后可恢复参考。

检查发生在导入读取过程中及后续取用参考时，没有增加后台轮询。父目录变化没有产生原文件事件时，不承诺界面在完全空闲且没有取用参考的情况下立即刷新。该检查也不宣称排除任意并发写入者在最后一次检查之后继续修改文件的所有竞态。

## 回归和边界

四项新增原生回归覆盖：不同／相同内容替换父目录、恢复旧路径后保持失效、定义文件独立失效与重新导入、Karabiner 副本及冲突证据撤销、解析期间替换目录不能完成导入。

本地验证通过：100 项原生测试（81 项 Karabiner／固件、18 项文件导入、1 项生产装配），Debug 测试构建及未签名通用 Release 构建。日志为 `/private/tmp/keyrecord-import-replacement-native.log`、`/private/tmp/keyrecord-import-replacement-final-build.log` 和 `/private/tmp/keyrecord-import-replacement-release.log`。本批未修改 Swift package 源码，完整 package 回归交由对应提交 CI 执行。

自审核对通知发生在锁外、取消后不访问已关闭的文件句柄、事件与同步检查并发时失效状态不被恢复，以及旧通知不能清除重新选择的新文件。真实设备 HID、真实 Keychain 恢复、真实卸载和发布验证继续后置；未改变生产支持和删除前复核。
