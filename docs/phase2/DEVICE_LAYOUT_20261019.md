# 第六批：设备与布局参考对应

日期：2026-10-19。基于第五批合并提交 `5f165ab5d67e1799317b5f97d351cde13059d4a5`，该提交 main CI 已成功。本批使用模拟系统端口、临时配置与原生离线测试；真实设备、Keychain 恢复、卸载和发布验证后置。

## 具体缺口与实现

此前系统快照只记录服务编号与按键映射属性。即使已导入 VIA 配置及物理定义，也无法判断当前键盘服务是否与该定义型号相同，更无法发现服务编号未变但身份字段变化。本批实际原生属性端口增加 `VendorID`、`ProductID` 和 `Transport`，保留缺失状态，不收集序列号，不打开设备或写属性。

纯来源采集器逐服务读取，并在返回前再次核对身份和服务集合。分析层把当前已匹配的 VIA 配置/定义与系统快照连接：要求几何可解析、服务身份完整、厂商/产品编号一致且候选唯一，并限定 USB 编号体系。结果携带本次服务编号、布局名称及原始几何；其他情况返回明确原因。大于 16 位的设备编号不会截断成 VIA 编号，布尔、负数、非整数及错误类型不会当有效身份。

正式“重新检查”入口显示设备与布局的对应状态。对应成功也只表示唯一 USB 服务与所选文件型号相同；型号可能共用、定义可能选错版本、虚拟设备也可报告 USB 连接，因此不提升 `PhysicalDeviceEvidence`，不填充完整反向映射，不改变物理比较资格。原组合和候选继续一起按逻辑按键数比较。

## 失效与范围

- 同型号多个服务不自动选第一个，也不按数量推断物理键盘。
- 身份字段缺失、没有服务、型号不符、非 USB 连接或几何含未知布局选项，均不生成对应结果。
- 使用前复核整份系统快照；服务编号相同但属性变化、同型号服务替换、文件替换、后端切换或隐私撤销均撤回旧对应。值或文件恢复不复活旧观察，必须重新选择有效文件并重新检查。
- 文件在后台采集时失效，迟到结果不能保存。既有文件身份监测、取消和会话复核保持有效，无定时轮询或浏览器实例绑定。
- Vial 不借用 VIA 文件几何；Vial 自身定义几何、非 USB 身份来源、真实布局版本/选项和历史输入设备归属仍是独立缺口。固件活动层/时序、完整软件及 macOS 变换仍未补齐。

## 离线验证

新增核心测试执行属性解析、逐服务采集与二次身份读取，覆盖唯一匹配、缺失/重复/不匹配、连接方式、布局选项及采集中身份变化。原生测试通过实际来源适配器与临时 VIA 文件验证同服务身份变化、同型号设备更换、多设备歧义、文件原子替换、后端切换、隐私关闭和采集中来源失效。生产组合测试使用底层模拟来源端口执行正式路径；中英文 AX 界面验证对应信息和逻辑回退，并检查撤销后旧对应文字消失。

本地全量包测试 824 项通过，原生离线回归 127 项通过（107 项映射/文件流程、18 项导入、2 项生产组合/退出），arm64 Debug build-for-testing 通过。自审补强身份→映射→身份复核顺序后，12 项相关核心测试和全部原生回归再次通过。中英文截图已检查，对应信息与逻辑回退可读。

自审重点为型号匹配不得提升真实设备资格、旧关联不得复活，以及 Vial 不跨用 VIA 几何，无剩余阻断项。未新增 hash、冻结 contract、baseline 或 gate，未改变兼容目录、恢复副本或删除前复核。PR、push 及合并后 main CI 结果以本批实际运行记录为准。

原生属性读取沿用 [Apple IOHIDServiceClientCopyProperty](https://developer.apple.com/documentation/iokit/2269430-iohidserviceclientcopyproperty?language=objc)。Apple 的 [vendorID 说明](https://developer.apple.com/documentation/corehid/hiddeviceclient/vendorid)指出不同连接可能使用不同厂商编号体系；[虚拟设备 transport 说明](https://developer.apple.com/documentation/corehid/hidvirtualdevice/properties/transport)表明连接类型不能证明是物理设备。上述 API 文档仅用于实现依据，不代表本批运行了真实设备验证。
