## 1. 背景与产品定位

### 1.1 背景

自定义键盘用户在 macOS 上面临两条割裂的改键路径：软件层的 Karabiner-Elements，与键盘固件层的 VIA/Vial。用户通常凭感觉决定改哪个键、在哪一层改，缺少"我最常用哪些快捷键、哪些键位最费力"的事实依据，改错了也缺乏安全的验证与回滚手段。

本产品先把使用行为量化（全部在本地），再给出可解释的映射建议，最后把映射安全地落到用户选择的后端，并提供验证与回滚。

### 1.2 定位

面向广大自定义键盘爱好者的 macOS 菜单栏应用：本地统计快捷键使用，给出确定性、可解释的映射推荐，支持把映射安全应用到 Karabiner-Elements 或键盘固件（VIA/Vial），并支持验证与回滚。不针对任何特定职业垂类。

一句话：先量化，再改键，可回滚。

### 1.3 产品目标

- G1：让用户看到真实的快捷键使用分布（统一以阶段 3 观测口径统计）。
- G2：给出确定性、可解释的平衡评分推荐，而非黑盒建议。
- G3：让用户安全地把映射应用到所选后端，可验证、可回滚。
- G4：全过程中行为数据不出设备。

### 1.4 成功衡量

本产品不内置遥测，成功指标通过发布渠道与自愿用户反馈定性评估，不采集任何行为数据：

- 新用户能完成首个采集周期，并从推荐创建至少一条映射。
- 每条已应用映射都存在可用的验证与回滚路径。
- Beta 后端（VIA/Vial）的阻断与警告路径可被用户正确理解。

## 2. 目标用户与使用场景

### 2.1 目标用户

广大自定义键盘爱好者：拥有或计划拥有支持 VIA/Vial 的键盘，或在 macOS 上使用 Karabiner-Elements 的用户。不限职业、不限技术水平。按熟悉程度分三档：

- 新手：从未改过键，想知道从何入手。
- 进阶：用过 Karabiner 或 VIA，想让改键更有依据。
- 资深：多把键盘、多层布局，需要批量、安全、可回滚的生成工具。

### 2.2 典型场景

- S1：新手想知道哪些快捷键最常用、能否少按一个键。
- S2：进阶用户想把高频应用快捷键从软件层固化到键盘固件。
- S3：资深用户想基于最新布局备份批量生成 VIA/Vial 补丁，并能整体回滚。
- S4：隐私敏感用户要求数据不出本机、可随时暂停、可随时彻底删除。

### 2.3 明确不服务

- 需要云同步、多端统一的用户（非目标 N1）。
- 需要宏、连发、Tap Dance 等高级玩法的场景（非目标 N11、N12）。

## 3. 术语与四阶段输入模型

### 3.1 四阶段规范模型（Canonical Stages）

```
[阶段 1] 物理输入
   用户按下/释放键盘物理键
        |
        v
[阶段 2] 固件输出
   键盘固件（含 VIA/Vial 配置）发出的 HID 键码
        |
        v
[阶段 3] 应用侧 macOS 事件观测
   经受支持的改键路径（Karabiner-Elements 与 macOS
   软件层）变换后，本产品在 macOS 事件流上观测到的、
   面向应用的快捷键事件（含修饰键状态）。
   这是对事件的观测，不证明应用已收到或已响应
        |
        v
[阶段 4] 应用/系统效果（未观测）
   应用或系统实际产生的功能效果，本产品不观测
```

规范约定（全书一致）：

- 使用频率：一律以阶段 3 的事件观测为准统计；阶段 3 不代表应用已收到或已处理该快捷键。
- 应用归属：在快捷键终止键按下时刻取前台应用状态。可靠观测到应用时使用其 bundle ID；可靠确认前台上下文无可用 bundle ID 时计入"未知归属"桶；前台状态不可靠或不可判定时失败关闭，不计数（详见 5.2）。
- 物理负担：对阶段 1 物理动作的估算。物理口径要求完整证据链：布局几何、已验证固件的阶段 1→2 映射、以及相关阶段 2→3 变换（含相关 Karabiner 与 macOS 变换）全部可验证且无歧义；布局预设仅提供几何信息，不提供阶段 2 映射。任一环节缺失、歧义、不受支持、多设备不确定或已外部变更时，只展示逻辑按键数（和弦键数）的减少，而非物理动作减少，并标注置信度（详见 7.1、7.5）。
- 阶段 2 映射信息仅来自已验证的固件配置；用户选择的布局预设只提供阶段 1 的几何估算信息，不提供阶段 2 映射。
- 阶段 4 不被观测。经可选辅助功能权限读取的目标应用菜单快捷键只是部分证据，不构成阶段 4 的证明（详见 9.2）。

### 3.2 术语表

| 术语 | 定义 |
|---|---|
| 周期（Cycle） | 一次采集统计的完整过程，无固定时长，由用户开始、暂停、恢复、重置 |
| 活跃日（Active Day） | 存在有效计数的本机自然日（以本地日期键为准） |
| 半衰期 | 频率衰减参数，固定为 14 个活跃日 |
| 观察候选 | 已出现在统计中但未达正式推荐门槛的快捷键 |
| 正式推荐 | 通过推荐资格门槛（原始计数不少于 20 次，且分布在不少于 2 个不同本机自然日）的快捷键 |
| 触发（Trigger） | 映射的输入侧：单键或修饰键组合 |
| 输出（Output） | 映射的目标侧：一个快捷键 |
| 作用域（Scope） | 映射生效范围：全局或指定应用（bundle ID） |
| 后端（Backend） | 映射落地位置：Karabiner-Elements、VIA、Vial |
| 受管规则 | 由本产品创建、命名空间隔离的规则，与用户既有规则严格区分 |
| 受管块 | Karabiner Profile 内由本产品维护的连续规则块 |
| 未知归属桶 | 已可靠观测前台上下文、但该上下文无可用 bundle ID 时使用的统计归类，计入作用域分布分母；前台状态不可判定时不使用该桶，而是失败关闭 |
| 基线（Baseline） | 用户最近一次经官方工具导出的固件布局文件，作为固件生成的唯一起点 |
| 版本轴 | VIA/Vial 兼容性的独立维度：定义 schema、设备协议、布局备份格式、键码方言、导入器兼容性 |
| 裸键 | 不带修饰键的单键按键 |
| Secure Input | macOS 安全输入模式（如密码框）；期间或其状态不可确定时不采集任何数据（失败关闭） |

## 4. 端到端核心流程

### 4.1 首次使用主流程

1. 首次打开：展示采集内容与隐私边界，询问是否开始采集；用户同意前不采集任何数据。
2. 周期开始：统计阶段 3 快捷键与裸键计数。
3. 达到推荐门槛：菜单栏出现徽标提示，不使用打断式弹窗。
4. 用户打开主面板：查看 Top 5 推荐与全部候选。
5. 选择一条候选，进入映射创建流程：选择映射方式，后端配置，作用域，新触发，冲突检查，确认。
6. 应用并验证；必要时回滚。
7. 应用映射后提示是否开启新周期，用户可拒绝并继续当前周期。

### 4.2 数据流

```
键盘 --HID--> macOS / Karabiner --> 应用
                  |
                  v  （阶段 3 事件观测旁路计数，仅本地）
           采集运行时 --> 本地加密存储 --> 推荐引擎（本地）
                                                |
                                                v
                                        映射生成 --> 后端
                        （Karabiner 直接原子写入 / VIA 导出补丁 / Vial 导出 .vil）
```

注：图中事件流向应用的下游（阶段 4）不在本产品观测范围内。

## 5. 采集与统计生命周期

### 5.1 生命周期规则

- L1：首次打开必须显式询问用户是否开始采集；未同意前不采集任何数据。
- L2：周期无固定时长；支持开始、暂停、恢复、重置（开启新周期）。
- L3：退出应用仅停止采集运行时，保留"期望采集中"的状态；重新打开自动恢复同一周期。
- L4：登录启动项在设置中显式展示；仅在用户开始采集之后才默认开启。
- L5：重置/新周期删除明细统计，保留汇总、已应用映射、备份、已忽略项与偏好。
- L6：应用一条映射后提示开启新周期，用户可拒绝并继续当前周期。
- L7：暂停采集不影响已应用映射的生效。

### 5.2 计数语义

- C1：一次"按下到释放"计一次；按住产生的自动重复（auto-repeat）不计入。
- C2：带产品标记的自身测试事件保证排除。对其他疑似合成或注入来源的事件不做普遍剔除，仅降低置信度并在 UI 标注；识别能力边界见未决事项 O7。
- C3：左右修饰键在内部独立记录，UI 默认合并展示，可展开查看。修饰键状态依赖事件流重建；发生事件丢失、tap 重置或系统唤醒后，修饰键状态置信度标记为未知，直至重新建立。
- C4：使用频率以阶段 3 的事件观测为准。
- C5：系统快捷键（如截图、调度中心）单独识别归类，推荐时默认全局作用域。
- C6：离散快捷键才可进入推荐与映射。Cmd-Tab 类按住/有状态快捷键仍在统计中可见，但不进入推荐、不可发起映射。
- C7：应用归属在快捷键终止键按下时刻取前台状态：可靠观测到应用时使用其 bundle ID；可靠确认无可用 bundle ID 时计入"未知归属"桶。
- C8：Secure Input 期间，或安全输入/前台状态不可靠、不可判定时，一律失败关闭：所有计数器零更新，不进入"未知归属"桶。

### 5.3 采集状态模型

```
                 首次打开
                    |
                    v
            +---------------+
            |    未开始      |
            +---------------+
                    | 用户同意开始
                    v
  +----------+   恢复   +-----------+   暂停   +----------+
  | 新周期    | <------ |  采集中    | ------> |  已暂停   |
  +----------+          +-----------+          +----------+
       ^                     |
       |        重置（删除明细，保留汇总/映射/备份/忽略项/偏好）
       +---------------------+

  退出应用：运行时停止，"期望采集"状态保留
  重新打开：自动恢复到退出前的期望状态，周期不变
```

### 5.4 功能需求（采集）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-C1 | 首开询问 | 首次启动出现采集说明与开始入口；点击开始前无任何计数写入 |
| FR-C2 | 暂停/恢复 | 暂停后计数停止且已应用映射仍生效；恢复后继续累计 |
| FR-C3 | 退出恢复 | 退出应用后重开，自动恢复到退出前状态且周期不变 |
| FR-C4 | 登录启动 | 设置中可见登录启动开关；仅在已开始采集后默认为开 |
| FR-C5 | 重置保留项 | 重置后明细统计为空；汇总、映射、备份、忽略项、偏好均保留 |
| FR-C6 | 计数语义 | 连续按住一键 3 秒只计 1 次；带产品标记的测试事件保证不计入 |
| FR-C7 | 归属与失败关闭 | 终止键按下时刻取前台状态；可靠无 bundle ID 时入未知归属桶；前台状态不可靠或不可判定、Secure Input 活跃或状态不确定期间各计数器零变化 |
| FR-C8 | 持续快捷键 | Cmd-Tab 在统计中可见，但不进入推荐且不可发起映射 |

## 6. 隐私与数据安全

### 6.1 基本原则

- P1：行为数据永不离开设备。唯一联网行为是更新检查。
- P2：不存储任何可还原的文本内容（不记录输入字符串、键序、窗口标题、文档内容）。
- P3：显式的暂停/恢复入口始终可用。
- P4：本地数据使用经认证的加密存储，密钥为仅存本机、不同步的 Keychain 密钥项；不提供明文回退模式（详见 6.3）。
- P5：完整备份使用用户密码经独立的、加盐的版本化 KDF 信封加密；常规导出（映射/偏好）不含统计数据。

### 6.2 数据分类与存储规则

| 数据 | 粒度 | 允许包含 | 禁止包含 |
|---|---|---|---|
| 快捷键统计 | 日聚合 | 快捷键组合、次数、来源置信计数（普通观测/疑似合成）、应用 bundle ID | 序列、精确时间戳、任何文本 |
| 裸键计数 | 日计数器 | 键码、次数、来源置信计数（普通观测/疑似合成） | 序列、精确时间戳、应用归属 |
| 排除应用前台期间 | 不记录 | 无 | 任何计数（含"曾发生按键"类元计数） |
| Secure Input 期间 | 不记录 | 无 | 任何计数 |
| 固件原始/导入文件（VIA/Vial）、宏等敏感内容 | 静态加密、不索引 | 原样加密存储 | 索引、检索；改动未知或宏子树 |

- 固件类敏感内容仅在内存中由有界的、保留原始内容的解析器瞬时解析；未知与宏子树保持不透明、不被修改（详见 8.3、8.4）。
- P6：排除应用前台期间、Secure Input 期间，以及安全输入/前台状态不可靠或不可判定时，所有计数器零更新（失败关闭）；可靠确认无可用 bundle ID 的前台上下文按 C7 计入未知归属桶。
- P7：用户可随时删除全部本地数据（见卸载准备流程，10.3）。

### 6.3 加密边界与密钥生命周期

- EK1：应用管理的本地存储一律经认证加密；加密密钥为仅存本机、不随任何云同步的 Keychain 密钥项。
- EK2：不提供明文回退模式；事件数据不以明文写入日志或临时文件。
- EK3：密钥缺失或不可用时失败关闭：采集与读取停止，不生成任何本地明文副本。
- EK4：完整删除（卸载准备流程）包含 Keychain 密钥材料。
- EK5：完整备份使用用户密码经独立的、加盐的、版本化 KDF 派生密钥的信封加密，与本地存储密钥相互独立；具体算法选型由技术架构文档确定。
- EK6：两类明文边界在产品加密边界之外：用户显式选择的导出文件，以及 Karabiner 自有的配置文件。涉及这些边界时 UI 明确提示。

### 6.4 网络边界

- 唯一网络请求：每周一次的更新检查；安装更新前必须经用户确认。
- 无遥测，无崩溃自动上报。

### 6.5 权限模型

| 权限 | 必要性 | 用途 | 拒绝后果 |
|---|---|---|---|
| 输入监控 | 必需 | 阶段 3 计数 | 核心统计不可用，引导用户授权 |
| 辅助功能 | 可选 | 仅在用户发起时，按需读取目标应用的菜单快捷键 | 不阻塞映射；相关冲突与效果提示降级 |
| 登录项 | 可选 | 开机自启 | 无 |

辅助功能权限边界：只读目标应用的菜单快捷键；不读取窗口、标题、文本、焦点控件等任何其他信息。

### 6.6 功能需求（隐私）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-P1 | 数据不出设备 | 抓包验证：除更新检查外无任何网络外发 |
| FR-P2 | 不可还原文本 | 数据库与日志中不存在可还原的键序或文本 |
| FR-P3 | 裸键计数最小化 | 裸键日计数器无序列、无精确时间戳、无应用归属字段 |
| FR-P4 | 排除与失败关闭 | 排除应用、Secure Input 及状态不确定期间各计数器零变化 |
| FR-P5 | 加密存储 | 本地数据经认证加密；密钥为仅本机、不同步的 Keychain 项；无明文回退；日志与临时文件无事件数据明文 |
| FR-P6 | 备份加密 | 完整备份使用独立加盐版本化 KDF 信封，须密码解密方可恢复；常规导出文件不含统计表 |
| FR-P7 | 密钥生命周期 | 删除或损坏 Keychain 密钥后启动：采集停止且无本地明文副本；完整删除后 Keychain 材料不存在 |

## 7. 推荐系统

### 7.1 评分模型

- R1：仅使用确定性、可解释的平衡评分。相同输入必得相同输出，无随机成分，无黑盒模型。
- R2：评分因子全部对用户可见、可解释：
  - 使用频率：阶段 3 加权频率，按 14 个活跃日半衰期衰减。
  - 物理负担：仅在完整证据链（布局几何 + 已验证固件阶段 1→2 映射 + 相关阶段 2→3 变换全部可验证且无歧义）下为物理估算；布局预设仅提供几何、不提供阶段 2 映射；任一环节缺失、歧义、不受支持、多设备不确定或已外部变更时，仅以逻辑按键数（和弦键数）口径参与，并标注置信度。
  - 置信度：事件来源可靠性、布局信息完整度。
  - 作用域分布：应用集中度。
- R3：每条推荐展示理由的因子分解，例如："近 14 个活跃日使用 86 次；每次 3 键；建议触发 2 键；应用集中度 82%"。

### 7.2 推荐门槛与候选

- R4：正式推荐资格门槛：原始周期计数累计不少于 20 次使用，且分布在不少于 2 个不同的本机自然日。14 活跃日半衰期仅用于排序，不影响资格判定。

- R7：首页展示 Top 5 推荐与全部候选列表。
- R8：每个候选项最多给出 3 个触发候选。
- R9：仅展示预估的按键次数减少：证据链完整时为物理动作估算，否则为逻辑按键数口径；不展示、不承诺时间节省或健康收益。

### 7.3 作用域规则

- R10：每张 Karabiner 推荐卡片都提供"高频应用"与"全局"两个作用域选项。
- R11：候选应用不含未知归属桶；若加权 Top 应用占比不低于 70%（分母仍包含未知归属桶），默认选中应用作用域；否则默认全局。占比平分按 bundle ID 规范序取先。统计中没有已知应用时默认全局，应用作用域选项不可用并附说明，用户不能改到无效应用作用域；存在至少一个有效已知应用候选时，用户始终可改。

### 7.5 人体工学评分（基础版）

- E2：有几何数据时使用真实 VIA/Vial 布局几何；否则由用户选择 ANSI / ISO / Alice / 分体预设（预设仅提供几何，不提供阶段 2 映射）；两者都没有时退化为仅按键数与修饰键数。

### 8.2 Karabiner-Elements 细则

- K1：默认后端，发布状态稳定。
- K2：仅在用户选择"应用"时才安装或调用；未应用前不改动系统。
- K3：写入方式：对当前或用户所选已测试 Profile 的修补，采用基线哈希乐观并发。写入前校验 Profile 当前哈希与读取基线一致，不一致则中止并按外部变更处理；以同目录原子替换方式落盘；写入后读回校验。
- K4：受管规则组织为 Profile 内一个连续的受管块，使用独立命名空间。用户既有规则的相对顺序与内容保持不变；已知会与用户规则重叠的情形按冲突阻断，而非静默调整用户规则。
- K5：统计合并所有 Profile；映射绑定到单个 Profile。
- K6：触发支持单键或修饰键组合，输出为快捷键。
- K7：默认作用于全部键盘，可选限定设备。
- K8：同一触发可在互不重叠的应用作用域中有不同映射；作用域重叠视为冲突。
- K9：不生成链式或双向循环映射。
- K10：未知 Karabiner 版本：只读与导出，不写入。
- K11：检测到外部编辑时提示用户三选一：采纳外部变更、重新应用受管规则、停止管理。
- K12：批量应用为一次事务：每批产生一份加密前镜像备份，原子替换落盘，读回校验；任一步失败时按当前文件哈希分类处理：仅当当前哈希仍等于本产品写入结果时自动恢复到前镜像；等于读取基线时视为提交未落盘、仅标记失败且不写文件；两者皆非按外部变更处理，禁止自动写入。
- K13：崩溃协调：启动时检测上次写入是否完成，并按当前文件哈希三分类处理：等于本产品写入结果时，允许自动完成收尾或按用户请求回滚到前镜像；等于读取基线时，视为提交未落盘，仅标记失败且不写文件；两者皆非一律按外部变更处理（见 K11），禁止任何自动写入。

### 8.3 VIA 细则

- V1：Beta 状态。V2/V3 指定义 JSON 的格式版本；整体兼容性按 8.1 的五个版本轴判定。
- V2：用户可导入未随产品捆绑的厂商定义 JSON。
- V3：每个批次都从用户最近一次经官方工具导出的基线出发；无最新基线时阻断生成。基线与产物均记录来源哈希，用于一致性与回滚校验。
- V4：产品只做安全修补与导出，用户通过官方 VIA 导入；产品不直接写设备。
- V5：仅使用现有可达层。自动候选仅允许一步 MO/LT；TG/TO 仅手动；不新建层、不修改层入口。
- V6：KC_TRNS 默认视为占用；KC_NO 可作为自动候选。
- V7：任一必需版本轴未知或不受支持：阻断生成。
- V8：实验性设备允许使用，并给出警告。
- V9：生成前校验设备身份、布局与层同基线一致；只修补用户选中的键位槽，其余内容原样保留；未知/自定义键码原样保留，绝不自动选用。
- V10：原始与导入的 VIA 文件、宏等敏感内容静态加密且不索引；仅在内存中由有界的、保留原始内容的解析器瞬时解析；未知与宏子树保持不透明、不被修改。

### 8.4 Vial 细则

- VL1：Beta 状态，产品能力与 VIA 对齐；不生成 Combo、Tap Dance、宏、Key Override。
- VL2：通过协议层面非变更的、白名单化的 HID 查询获取 UID、定义与布局；禁止解锁及任何变更类命令。
- VL3：唯一交付物是修改后的 .vil 文件，用户经官方 Vial 导入；产品不写设备、不处理解锁。
- VL4：仅全局；仅现有可达层；未知版本阻断。
- VL5：敏感宏与配置数据按 V10 同款规则处理：静态加密不索引，未知子树不透明不改动。

### 9.2 冲突检测分级

| 级别 | 内容 | 处理 |
|---|---|---|

- X3：应用菜单快捷键的冲突检测依赖可选的辅助功能权限；拒绝授权时降级为提示级，不阻塞映射。

## 10. 应用、验证与回滚

### 10.1 映射状态模型

```
Karabiner 路径（直接写入）：

 +-------+   应用    +---------+   读回校验   +---------+          +---------+
 |  草稿  | -------> |  已写入  | ----------> |  待验证  | -------> |  已验证  |
 +-------+          +---------+             +---------+          +---------+
                         |                                            |
                         v                                            v
                   +------------+                                  +------+
                   |  外部变更   |                                  | 失败  |
                   +------------+                                  +------+

固件路径（VIA/Vial：导出加用户经官方工具导入）：

 +-------+  导出成功（原子：产物记录 + 状态迁移）  +--------------+  用户声明已导入  +------------------+
 |  草稿  | -----------------------------------> | 等待用户导入  | -------------> |  用户声明已导入   |
 +-------+                                       +--------------+                +------------------+
                                                       | 放弃产物（仅删除产物）          | 验证
                                                       v                               v
                                                    草稿                        +-------+   +------+
                                                                                | 已验证 |   | 失败 |
                                                                                +-------+   +------+

 通用：任一持久状态检测到外部修改即转为"外部变更"；Karabiner 的"已写入/待验证/已验证/失败"可按哈希规则回退为"已回退"；固件的"用户声明已导入/已验证/失败"经导入原始基线的引导回退为"已回退"，导出后未声明导入状态仅可放弃产物。
```

状态集合：草稿、已写入（仅 Karabiner）、等待用户导入（AwaitingUserImport，仅固件）、用户声明已导入（ImportClaimed，仅固件）、待验证、已验证（Verified）、失败（Failed）、外部变更（ExternallyChanged）、已回退（RolledBack）。导出成功是产物操作的结果（记录于产物与批次），不是独立的映射状态；它与映射进入"等待用户导入"原子发生。

关键语义：固件路径中，产物文件已生成不代表设备已部署；设备状态只有经对应后端的验证方式确认后才记为"已验证"；用户声明导入不构成验证证据。

- A1：每条映射展示状态、验证来源与验证时间；固件路径同时展示导出时间与用户声明导入时间。
- A2：验证方式按后端区分：Karabiner 支持持续配置验证（读回比对）；Vial 在非变更白名单连接时比对；VIA 以用户行为测试确认为准。导出不等同部署；导入声明不构成验证证据。
- A3：行为验证采用安全方式。Karabiner 应用作用域测试使用临时的 KeyRecord 命名空间等效规则，测试结束后或下次启动时清理。

### 10.2 批次与备份

- A4：Karabiner 批量应用等于一次事务：基线哈希校验、同目录原子替换、一份加密前镜像备份、写后读回校验。
- A5：VIA 每批基于用户最新导出基线并记录来源哈希；Vial 每批对应一个 .vil 并记录来源哈希。

### 10.3 回滚与紧急停用

- A6：菜单栏提供鼠标一键停用本产品的 Karabiner 规则，立即生效，可恢复。
- A7：固件回滚通过官方工具加备份完成，产品内提供引导：用户声明已导入、已验证、失败状态提供导入原始基线的引导；导出后未声明导入状态仅可放弃产物，不涉及设备。
- A8：卸载准备流程：先保障固件恢复基线（导出到用户选择的位置，或用户显式确认另行持有副本；选择不保留则醒目警告并记录确认），再移除受管 Karabiner 规则、登录项与本地数据，并向用户说明固件恢复方式。

### 10.4 功能需求（应用与回滚）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-A1 | 状态展示 | 每条映射有状态、验证来源与验证时间；固件路径的导出事实与导出时间可见；仅导出未导入时不得显示为已生效；导入声明不构成已验证 |
| FR-A2 | 临时规则清理 | 应用作用域测试后无残留临时规则，含异常退出后的下次启动 |
| FR-A3 | 一键停用 | 菜单栏停用后 Karabiner 规则立即不生效，且可恢复；支持版本上从点击到受管规则失效不超过 2 秒（p95） |
| FR-A4 | 卸载准备 | 删除本地数据前已导出或显式放弃固件恢复基线；执行后无受管规则、无登录项、本地数据按用户选择删除，固件恢复说明可见 |

## 15. 验收总结（发布门禁）

以下各项全部通过，方可认为 v1 达到本 PRD 要求。

隐私与安全：

1. 除更新检查外零网络外发（抓包验证）。
2. 数据库与日志无可还原文本；裸键计数无序列、无精确时间戳、无应用归属。
3. 排除应用、Secure Input 及安全/前台状态不确定期间计数零变化（失败关闭）。
4. 本地数据经认证加密、仅本机不同步 Keychain 密钥、无明文回退、密钥缺失失败关闭；完整备份使用独立加盐版本化 KDF 信封。

采集与推荐：

5. 首开询问、暂停/恢复、退出恢复、重置保留项行为符合第 5 章。
6. 评分确定性；资格门槛为原始计数不少于 20 次且跨不少于 2 个本机自然日；14 活跃日半衰期仅影响排序。
7. 首页 Top 5、每项不超过 3 个触发候选、仅按键次数估算。
8. 作用域默认值按 70% 规则给出；存在有效已知应用候选时用户可改，无候选时应用作用域不可选。

映射与回滚：

9. Karabiner 基线哈希乐观并发、同目录原子替换、读回校验、每批一份加密前镜像、读回不一致按哈希分类处理、崩溃协调与受管块隔离全部生效。
10. VIA/Vial 仅导出补丁或 .vil，对设备无写入或解锁命令；任一必需版本轴未知即阻断；导出不等同部署。
11. 冲突三级处理正确；高风险二次确认；证据不足按提示级。
12. 映射状态模型完整（含固件导入声明与验证状态）；导入声明不构成验证证据；验证来源与时间可见；菜单栏一键停用可用且达标（2 秒 p95）。
13. 备份策略正确：滚动 10 份、固件基线与批次备份保留、导出边界清晰。

UX 与平台：

14. 菜单栏优先、双语、完整键盘操作与 VoiceOver。
15. macOS 14+ 双架构；资源预算达标；无守护进程。
16. 更新检查每周一次且安装需确认；无遥测。
17. 发布物签名并公证（FR-S6）。
