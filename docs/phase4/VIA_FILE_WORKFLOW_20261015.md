> 历史记录说明（2026-10-20 核对）：本页保留所述日期/提交的实现、命令和验证范围，其中“当前”“待实现”“下一步”仅指当时。功能开发已暂停，最新状态见 [PROJECT_STATUS](../PROJECT_STATUS.md)，后续安排见 [ROADMAP](../ROADMAP.md)；本页不授权新实机、设备或删除操作。

## 产品方向

用户于 2026-10-15 明确提出由用户导出最新 VIA 配置。当前方向采用文件工作流：从 VIA 导出最新配置，导入 KeyRecord，保留原始副本；修改文件由用户手动导回 VIA 并检查。若用户之后又在 VIA 修改配置，应重新导出并选择文件。

浏览器运行实例绑定不再作为这一文件工作流的前置目标，不因此维护 VIA 分支或浏览器扩展。文件本身不证明导出时间、设备当前状态、在线导入器版本或真实兼容性。已有的兼容检查、保护入口、备份和导入后验证继续保留。

## 本次复现与实现

在 main `63d0657cf50c758cd9a9c49cc8c5dec1aa8881ce` 上，通过真实文件读取器加载一份合法 VIA 配置，不加载键盘定义。模型已经保留配置字节，但中英文原生视图均未提供配置概况；新增原生测试实际运行出现 4 个断言失败。

现在只选择配置文件即可显示名称、层数和第 0 层的标准／未支持配置数量。宏内容不展示，多层、未知动作和动态内容的限制仍明确显示。提示用户先从 VIA 导出最新配置，并在后续修改后重新导出。

键盘定义用于补充矩阵核对和位置参考。未选择定义时不构造矩阵坐标，不生成物理几何或距离证据。定义不匹配时仍显示错误，独立的配置文件概况不冒充匹配成功。补充合法定义后继续使用原有完整参考摘要。

新摘要复用原文件监测与隐私权限：文件替换、清除或隐私关闭后撤销；重新打开隐私权限不会自动恢复旧摘要。

## 验证与范围

原生回归覆盖中英文单文件概况、补充定义、多层及未知动作限制、宏内容不展示、原子文件替换、隐私关闭及重新打开。原有定义不匹配测试增加单文件参考仍存在的断言，矩阵匹配失败仍保留。

本地 96 项原生测试通过（81 项映射／固件、14 项文件导入、1 项生产组合），Debug 测试构建和未签名 arm64／x86_64 Release 构建通过。自审核对了摘要权限与原文件监测一致、错误提示不被单文件摘要覆盖、未构造几何证据、未改变生成权限和原始副本保存逻辑。

首轮 PR CI 通过，push CI 暴露既有 Karabiner 测试的时序假设：拒绝重新绑定后立即断言 `canManage`，但之前的文件写入可能仍触发目录监测对账，正常对账期间管理操作暂时禁用。测试改为在 5 秒内等待实际对账完成，再执行原来的管理资格、目标文件未改动及加密引用仍指向旧目标的断言；未修改生产逻辑，也未删减断言。

本批只完成文件导入入口及反馈，不声称完整的 VIA 修改文件生成流程已经可用。生产支持目录仍为空，未合格的修改生成继续被阻止；不会用“用户刚导出”替代兼容性证据。真实设备、真实 Keychain 恢复、真实卸载和发布验证继续后置，删除前复核保留。
