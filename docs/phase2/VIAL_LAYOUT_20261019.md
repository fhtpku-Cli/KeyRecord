# 第七批：Vial 自身定义与物理布局参考

日期：2026-10-19。基于第六批合并提交 `9dc9e88588e0e8c6822b70b8aa55f202bb75c080`；该提交 main CI 已通过。本批只执行模拟端口、临时配置和离线测试。

## 缺口与实现

Vial 只读流程此前已读取内嵌定义、验证 UID/VID/PID 和每层矩阵拓扑，但返回观察只含键码，定义未进入分析。因此即使读回完成，Vial 分析仍缺几何。

现在同次观察保留内嵌定义及其 UID，转换器再次核对 UID 一致。复用已有有界定义解析器能解释的简单 KLE 子集，生成 `layer:N/row,column` 坐标，与既有读回键码位置完全对应；各层都核对几何位置集合。坐标系标记为 Vial 定义参考，不从用户导入的 VIA 文件获取 Vial 几何。不存在定义时维持缺失；布局选项、旋转、装饰、未知几何及拓扑不符不生成几何。缺失 name 等解析信息也不猜测布局。

型号和坐标参考接入第六批的 USB 唯一匹配路径。只确认系统报告的型号与读回定义相同，不证明键盘服务就是该 UID 的物理设备、历史输入来自该设备或实际活动层。反向映射覆盖继续为空，完整链未成立，两组按键继续逻辑比较。界面明确“Vial 设备定义的读回快照，非实时映射”。

## 变化与清理

具体失败场景：设备在同一 UID 下、键码采集期间改变内嵌定义，旧坐标可能配上新键码。现有 UID/层数检查不能识别该变化，因此在键码采集完成后通过相同已授权只读连接再次读取完整定义，比较原字节；不同就拒绝本次结果。没有新增 hash、持久基线或资格门禁。请求尺寸、协议、授权、取消和断连检查继续由原端口执行。

设备服务替换、属性变化、来源通知、后端/软件来源变化或隐私撤销后，物理来源模型撤回相关 Vial 快照。重新检查系统属性不能把旧快照绑定到另一服务；必须在原恢复副本流程重新完成设备读回。撤销标记仅保留该内存快照的随机对象 ID，不保留旧布局或键码。新读取开始即撤回旧结果；取消、失败和隐私关闭不恢复它。定义身份核对发生在原确认事务之前。

本次读取结束仍关闭连接，未增加后台 HID 监听或定时轮询。设备内部后续变化只能通过后续显式读回发现，因此既不称实时映射，也不授予真实物理资格。

## 离线验证与边界

- 模拟协议实际执行两次定义读取，并复现 UID 不变、几何改变时拒绝结果。
- 多层键码的物理位置 ID 与定义坐标一致；缺失定义、UID 不符、拓扑不符、布局选项、旋转/装饰和 VIA 跨用均覆盖。
- 原生流程经实际读回适配器、临时加密资料库和模拟系统端口验证唯一型号匹配、同型号设备替换、失效后旧值恢复、重新设备读回及来源不可用。
- 最后一次定义读取暂停时关闭隐私，迟到报告被拒绝，连接释放。中英文原生界面展示非实时快照和逻辑回退。

自审检查完整链资格、事务顺序、旧来源不可复活及隐私清理，无剩余阻断项。兼容目录、恢复副本和删除前复核不变；不恢复浏览器实例绑定或定时任务。真实 HID/设备、Keychain 恢复、卸载及发布验证继续后置。活动层/时序、复杂或动态布局、非 USB 来源及历史设备归属仍待后续。
